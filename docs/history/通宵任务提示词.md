# 通宵任务提示词 · 方块世界

用途：睡前把「主提示词」整段粘给 AI（免费模型也行），早上按「早上验尸提示词」核对。
配套文件：`验收报告.md`（已做/未做清单）、`app/tools/selftest-package.ps1`（打包版自检）。

## 主提示词（整段复制，粘到会话第一条）

```
# 任务：通宵把《方块世界》从「已验收」推进到「更好玩」，不允许出现假完成

你在我本机的项目里工作，无人值守跑一整晚，早上我只看结果和证据，不看你的过程叙述。

## 0. 项目坐标（先自己读一遍再动手，不要凭猜）
- 根目录：E:\MinecraftOffline
- 源码：app          ← 一切代码改动都在这里
- 成品包：游戏\方块世界  ← 只由打包脚本产出，不要手改
- 现状文档：验收报告.md（第一节=已测通过 134 条；第二、三节=已知未做）
- 运行环境：Electron 单机离线游戏，纯中文界面，禁止任何联网请求、禁止新增 npm 依赖
- 关键源文件：renderer/js/core/{blocks,items,recipes,machines}.js、
  renderer/js/world/{world,chunk,terrain,mobs,lighting}.js、
  renderer/js/player/{game,controller,interaction,inventory}.js、
  renderer/js/ui/ui.js、renderer/js/gfx/painters.js
- 测试：app/tests/world.test.js（node --test，无头、秒级）、app/tests/e2e-scenario.js（GUI 剧本 134 条）

## 1. 第一条命令：建基线快照（没做这步，后面全是裸奔）
当前目录不是 git 仓库。开工第一步：
    cd E:\MinecraftOffline && git init && git add -A
    git commit -m "baseline: 通宵开工前快照（134/134 通过状态）"
然后立刻记录基线：
    cd app && node --test tests/world.test.js
把「基线：单测 N/N 通过」写进进度文件。之后每完成一个任务就 commit 一次。
铁律：不允许 git reset --hard 丢掉别的任务成果，不允许改 .git 里的任何东西。

## 2. 全程不许破坏的底线（任何时刻违反=这一晚白干）
- app/tests/world.test.js 现有 11 条必须始终全绿，只许增加新用例，不许删改既有断言
- renderer/vendor/three.module.js 是第三方文件，一个字节都不许改
- 不许大规模重构、不许改目录结构、不许改 package.json 里的依赖
- **禁止任何联网下载行为**：不许运行 `npm install` / `npm i` / `pnpm add` / `npm ci` / `npx <未安装的包>` /
  `git clone` / `curl` / `Invoke-WebRequest`。这台机器走手机热点，装一次 electron 就是 ~110 MB 流量，中途失败重试几轮
  能吃掉上 GB。现有依赖已经齐全，缺什么就用现成的写，写不出来就跳过该任务。
- 不许手改 游戏\方块世界 里的任何文件；成品只能由 node tools/pack.js 生成
- 存档格式如需变更，必须兼容旧存档（读不出旧档=失败）

## 3. 任务队列（按顺序做，做完一个再下一个，禁止同时开三个）
每个任务都写清了「验收命令」，验收不过就不算完成，继续修，修不动就回滚并如实标注「未完成」。
每完成一个任务：先跑单测 → 再 commit → 再进下一个。

### T1 锄头与独立耕地（优先，因为是文档里点名的缺口）
- 现状：blocks.js 里已有「耕地/小麦」方块和贴图，但没有锄头道具，也没有右键把草/泥土变成耕地
- 要做：
  1. 新增锄头道具（木/石/铁三档）与合成配方（木板/圆石/铁锭 + 木棍，走既有 RECIPES 结构）
  2. 手持锄头右键草方块/泥土 → 变成耕地，耐久 -1，播放既有音效（复用 sfx.js）
  3. 耕地湿润规则：3 格内有水=湿润（贴图/状态区分），干耕地在随机刻后变回泥土
  4. 种子物品：草方块破坏有概率掉种子；种子右键耕地上种植 → 长出小麦（既有小麦方块）
- 验收命令（必须贴出真实输出）：
    cd app && node --test tests/world.test.js          # 你新增的锄头/耕地/湿润用例全绿且 11 条老用例仍绿
    cd app && npx electron tests/e2e-electron.mjs     # 必须 通过 ≥134/134，不得出现 ✗

### T2 床与自定义重生点（文档点名缺口，逻辑集中在存档层，好验收）
- 要做：
  1. 新增床方块与合成配方（3 羊毛 + 3 木板）
  2. 夜晚右键床 → 睡觉：时间推进到清晨，生命/饥饿按原版规则恢复，白天睡觉给中文提示且不生效
  3. 睡觉把重生点改成床的位置，写进存档；死亡重生回到该床；床被破坏 → 重生点失效并回到出生点
  4. 存档往返：读档后重生点、时间、天气状态一致
- 验收命令：同上两条（必须为床的重生点/时间推进写出新的无头断言）

### T3 玩家用弓射击（文档点名缺口）
- 要做：
  1. 弓 + 箭：合成配方、蓄力（按住左键/右键蓄力，松开射出）、蓄力越久初速度越大
  2. 抛物线与命中：命中生物造成伤害（复用 mobs.js 现有扣血/死亡流程）；命中方块插在地上可拾回
  3. 箭是实体：用无头逻辑测试即可，不要在 GUI 里靠肉眼判断
- 验收命令：同上两条

### T4 时间允许时的加分项（可选，做不完不影响交付）
从 `验收报告.md` 第三节依次挑：红石/附魔/酿造/交易/新维度 → 更多生物与繁殖 →
门/梯子/栅栏类多方块结构 → 地图/指南针/成就/创造栏搜索。
规则：宁可一个做完并验收，也不要四个都改一半。改一半的必须在进度文件里标 `☠ 半成品` 并 git commit 说明。

## 4. 每个任务的固定工作流（照抄执行，不许跳步）
1. 读相关源文件，用 3 句话在进度文件里写下你的实现方案（写不出方案说明你没读懂，先读代码）
2. 只改最小必要的文件
3. 跑 `node --test tests/world.test.js`，不通过就修，修不好就把这次改动 git checkout 掉
4. 打包：`cd app && node tools/pack.js`
5. 打包版复验（必须用阻塞式启动，别用 Git Bash 直接跑 exe）：
    powershell -ExecutionPolicy Bypass -File app\tools\selftest-package.ps1
   期望：EXITCODE=0、RESULT_LINE=[自检] 通过 N/N、✗ 0 条、stderr 为空
6. `git commit -m "T{n}: <做了什么> | 单测 x/y | e2e a/b"`
7. 更新进度文件里该任务的状态行
8. （可选，我想看流量时）跑一次 `powershell -NoProfile -ExecutionPolicy Bypass -File app\tools\traffic-guard.ps1`
   把「实测速率 x MB/小时」记进进度文件。若数值明显高于 20 MB/小时，说明在打转或在下东西，立即停止下载行为

## 5. 反「假完成」硬规则（免费模型最容易犯的错，逐条遵守）
- 只有上述三条验收命令都跑过并贴出**真实输出**，才允许写「完成」
- 禁止出现「应该可以」「理论上通过」「已实现，未测试」这类措辞；没跑就是没做
- 每条命令的输出必须是复制粘贴的原文，包含路径/退出码/计数，不许改写或概括
- 自己新增的断言必须是真的会失败的断言：先在旧代码上确认它红，再让新代码把它变绿（把你验证过的「先红后绿」写一行进进度文件）
- 不许为了让测试通过而放宽断言、注释掉断言、改测试期望值来迁就实现
- 每完成一个任务就更新 `验收报告.md`：真实通过的功能进第一节（写明断言条数），
  没做成的写进第二/三节，绝不把没做成的写进已通过

## 6. 卡住与防挂死（无人值守最重要的一节）
- 同一个报错修 3 次仍不通过 → 放弃该任务，git 回滚，进度文件写 `✗ T{n} 放弃：<报错原文前 5 行>`，进入下一个任务
- e2e 或打包自检疑似卡住（超过 15 分钟没输出）→ 杀掉 electron 进程（Stop-Process -Name electron），
  改跑单测继续推进，并在进度文件记 `⚠ e2e/自检超时`
- 绝对禁止：直接运行 方块世界.exe 而不加 --selftest（会开出 GUI 窗口挂一夜）
- 绝对禁止：等待用户输入、问问题、留下 TODO 就停。不确定就先做「最小可用版本 + 无头测试」
- 上下文要省：不要把长日志、整份源码重复粘进对话；进度写进文件，对话里只写结论和数字

## 7. 进度文件（唯一的事实来源，必须一直维护）
路径：通宵进度.md（没有就创建），每次 commit 后更新，格式固定：
    # 通宵进度
    - 基线：单测 11/11、e2e 134/134、打包自检 EXITCODE=0（提交 abc1234）
    - T1 锄头与耕地：状态=完成 | 单测 15/15 | e2e 137/137 | 提交 def5678 | 证据=验收报告第一节
    - T2 床与重生点：状态=进行中 | 卡在=<具体现象>
    - ☠ 半成品：<文件名> 说明
    - 已回滚：T? <原因>
    - 明早待办：<1-3 条>

## 8. 停止条件
出现以下任一情况就**立刻停止**并写好进度文件，不要继续瞎试：
- 单测或 e2e 出现无法在 3 次内修复的失败
- 需要改动 vendor/、需要联网、需要新依赖
- 任务队列 T1~T3 全部尝试完毕（无论成败）
停止时最后一件事：确保工作区没有「改了但没提交」的残余（要么 commit，要么回滚干净）。

现在开始：先读项目文档和相关源码，然后执行第 1 节的基线提交，接着做 T1。
```

## 为什么这样写（给未来的自己看，不必粘给 AI）

| 提示词里的设计 | 防的是什么 |
|---|---|
| 第一条命令建 git 基线 | 通宵无人值守，改崩了没法回滚 |
| 任务队列按「文档点名缺口」排 | 免费模型自己选题会跑去改 UI 颜色这种无验收的事 |
| 每个任务绑定验收命令 + 必须贴原始输出 | 免费模型嘴硬说「已完成」，实际没跑 |
| 新断言要求「先在旧代码上变红」 | 防写永远为真的假测试来自证通过 |
| 明确禁止直接跑 .exe、超时杀 electron | 防 GUI 挂一夜空转（就是你上次 Git Bash 那个坑） |
| 3 次修不好就回滚换下一个 | 防一整晚卡在同一个 bug 上，早上零产出 |
| 进度文件 + 固定格式 | 早上只读一个文件就知道进度，不消耗上下文 |
| 停止条件写明 | 防止没收尾就断在半路，留下没提交的脏工作区 |
| 硬性「不新增依赖、不联网」 | 免费模型习惯性 npm install 会直接把离线性破坏 |
