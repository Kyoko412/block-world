本轮**没有出现「既有断言偶发红」**。这一夜一共跑了 **12 遍源码 e2e + 4 遍成品自检**（每段都是「红 → 定位 → 修 → 连跑两遍绿」的节奏），
每一遍我都 grep 过 `✗`：**失败条目只出现在我新写的断言上**，昨天记录的两个已知抖动 `AC.8`（成就条位置）与 `V5.4`（僵尸 8 秒没咬到盾）
一次都没有变红，也没有任何一遍是「重跑等它自己绿」的。

新写的断言里，我自己踩到并当场修掉的有 5 处，**全都是测试侧问题，不是产品缺陷，也没有一处是靠放宽阈值糊过去的**：

1. `A.3` 第一遍红（`leg0=-0.174` 不满足我写的 `< -0.3`）→ 原因是走路甩腿的相位会盖住前扑。改法是把断言换成**与相位无关的恒等式** `leg0 = legSwing - atkFront`、后腿 `= -legSwing`，比原来的绝对阈值更强。之后两遍 + 自检全绿。
2. 单测 `A2` 的 `headY === 0` 偶发 `-0`（`animIdle` 是随机的）→ 改成 `Math.abs(headY) === 0`，语义不变。
3. `B.6` 第一遍红（`caveEnter` 不动）→ `T.teleport` 走 `controller.spawnAt`，卡进石头会被顶出地面。改成先挖一条竖井再「高空 → 井底」两次采样。
4. `B.6` 第二遍红（目标音没被计到）→ `Sfx.play()` 对同名有 40ms 限流，放材料时成就先抢了那一声 `levelup`。改成过了限流窗口再取基线。
5. `C.1~C.4` 第一遍红 → `Inventory.set` 自己不发 `'change'`（要显式 emit 才会重画），以及熔炉面板只在事件里重画而 `T.furnacePut` 直接写模型。都改成走生产刷新路径。
