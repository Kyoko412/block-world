### 为何不照搬 `1200 秒`

把一整天从 600s 直接改成 1200s，会让所有等待昼夜/天气的 e2e 断言时长翻倍，成品自检逼近甚至越过 350s 上限；`dayLengthSeconds` 还被设置面板与存档使用。**必须先优化测试再动默认值**，因此排在 P2 独立一轮，不塞进第 0 刀。

## 第 0 刀落地记录（2026-11-05）

- **色彩空间**：`gfx/view.js` 的 `VOX_FRAG` 末尾补 `#include <colorspace_fragment>`。
  只改体素：`gfx/sky.js` 是另一套自定义 shader，混用硬编码 sRGB 数值与 linear 的 `THREE.Color`，一起改有 double-encode 风险；
  `entities.js`/`lightning.js` 用内置 `MeshBasicMaterial`（Three.js 自动处理）。天空/雾/实体/水的协调由 A/B 统计判断后再单独处理。
- **暗部校准**：补编码后 sRGB 对低线性值增益最大，洞穴整片发灰失去暗部。补一条按**最终颜色亮度**做的暗部系数
  `col *= mix(0.28, 1.0, smoothstep(0.02, 0.30, lum))`；白天与火把近处系数恒为 1。
  曾先试「按光照等级 lvl 补偿」，实测洞穴场景 `lvl` 本来就高、补偿完全不生效（`after` 与 `after2` 统计逐位相同），已改判据。
- **按键重复**：`input.js` 的双击 W 判定跳过 `e.repeat` keydown（原版体验优化提示词 P0 已复现的缺陷）。
- **取证**：`tests/shot-visual.mjs` 支持 `ab-*` 自定义隔离目录，并用 `nativeImage.toBitmap()` 出像素统计，不覆盖既有 `baseline/after`。
  同种子 `visual-audit-2026`、同时间 `0.3`、晴天、窗口 `1266×658`（物理像素 `1913×994`）、7 个场景。
  目录：`ab-20261105-before`（改前）/ `after`（只补编码）/ `after2`（lvl 补偿，无效）/ `final`（最终定稿），各含 7 张 PNG + `meta.json` + `stats.json`。
- **A/B 结论（已逐张开图确认）**：
  - `a-grass` 地面亮度 `0.225 → 0.483 → 0.436`；草地/树叶从近黑变亮绿、有层次、无过曝，中心暖色 `0.038 → 0.076`。
  - `c-cave` 地面亮度 `0.150 → 0.409 → 0.327`；暗部比纯编码版明显收敛，石砖仍可辨、无死黑或颜色断层。
  - **剩余差异（交给 P0 校准段）**：① 洞穴/夜间仍偏亮，火把附近暖色梯度不足（房间整体仍偏均匀灰）；
    ② 远景树线与天空仍脱节，怀疑与 `sky.js` / 雾色 `uFogColor` 的色彩空间有关，本刀未动，需单独核对。
  - 饱和度数值下降（如 `a-grass` `0.556→0.365`）是暗部被提亮后的相对变化，开图确认是「恢复层次」而非「洗白褪色」。
- 既有断言只增不减；`EXPECTED_TOTAL` 只增不减（505 → 507）。
