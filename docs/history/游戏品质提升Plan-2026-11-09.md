# 《方块世界》画风与玩法品质提升 Plan

审计日期：2026-11-09。审计基线：`3fe4b42`。本文件是审计后的实施计划，本轮没有修改游戏实现。

2026-11-10 音频专项补充：[音乐与音效审查](音乐与音效审查-2026-11-10.md)。已导出 31 种产品音效及场景对照，确认洞穴常驻低频占比和既有动作录音时序问题；本会话不支持音频输入，主观试听仍未完成。

当前最影响完成度的是材质、渲染、模型、空间和操作反馈之间的一致性。已有离线世界、负 Y 矿层、合成、鱼鸟、战斗与存档系统，足够支撑一轮品质收敛。建议先把一个小范围的探索—建造—战斗体验做好，再扩展内容。

## 1. 本次实际检查了什么

重新运行了当前包内 renderer 与最新源码 renderer，使用隔离存档和 1280×800 窗口。检查了主菜单、创建世界、三个种子的出生视野、林缘材质、天然村庄、水下自然鱼、天然负 Y 洞穴、火把照明、背包/创造栏、动物与敌怪对照、一次正常主循环里的近战命中、守卫站点、死亡/暂停/设置界面。

主要种子：`visual-audit-2026`、`12345`、`survival-01`；守卫现场使用 `guardian-2026` 的 `-2,0` 前哨。受控日景使用 time=0.3、晴天，视距 6、亮度 1、FOV 70；夜景单独标记。

证据有明确边界：生物对照使用了临时布置，洞穴火把和战斗装备也为取证准备；它们用于审查外观与反馈，不代表自然生存流程完成。使用程序输入观察了主循环，未做真人鼠标触感评测，未主观试听音乐，也未走完自然生存通关。没有把旧截图当作此次证据。

完整图文索引：[本轮审计证据](artifacts/quality-audit-20261109/审计证据.md)。

## 2. 为什么会显得廉价

| 问题 | 本轮证据 | 对体验的影响 |
|---|---|---|
| 水面和远景过于抢眼 | 05、11：水面长条与矩形拼块明显，水下像隔着蓝玻璃；远景形成浅蓝剪影 | 画面的大面积区域缺少可信的空间层次 |
| 主材缺少统一规则 | 06、10、15：木板像编织纹，草边形成连续横条，深板岩像铺满的人工层纹 | 单块可辨认，铺满地形后显得机械、重复 |
| 资产完成度不齐 | 19、20：动物/骷髅/苦力怕有贴图，僵尸与守卫仍是纯色块 | 同场角色像来自不同开发阶段 |
| 有真实缺失材质 | 31 的南瓜正面出现紫黑条纹；运行画笔探针返回失败 | 占位资源直接出现在正常世界里 |
| 第一人称存在感弱 | 05 空手无手臂；16 工具是很薄的平面，夜景武器与环境质感不协调 | 操作像推动一张图标，缺少握持与重量 |
| 地形和建筑空间单一 | 10 的平顶方盒建筑；15 的低矮、层高接近固定的深洞 | 有深度和建筑数量，探索、居住和建造的空间趣味仍弱 |
| 守卫与场地脱节 | 31：守卫在前哨屋顶；29/30 周围树冠遮挡，入口提示叠出 | 玩家难以自然读懂、接近和应对战斗 |
| 招式表达与实现有落差 | `guardianFire()` 的光弹按距离/视线直接扣血，没有实体弹道 | 侧移难以构成对“光弹”的直观应对 |
| UI 像开发样例界面 | 04、07、28：主菜单大块灰面板与技术说明，背包灰字层级弱，设置暴露 settings.json | 游戏氛围被技术说明与重复提示打断 |

保留已有优点：鱼确实自然生成；火把与黑暗有明显区分；近战有扣血、红闪、命中标记与击退；中文入口和基本物品操作已存在。后续应在这些基础上收敛。

## 3. 统一的美术方向

目标定为“清楚、克制、有材质差异的经典像素体素世界”。默认画面应有完整观感，光影增强可作为后续选项。

- **像素组织**：保留清晰像素边缘。以成组的像素表现木纹、石块和皮毛，减少逐像素随机噪声、满面高反差描边和到处出现的纹理亮点。
- **尺度**：方块、角色、工具使用协调的像素密度。角色按头、身、四肢的实际面积分配 UV，正脸、侧面、后脑和腹背分别处理，避免每个小面都塞一整张 16×16 正面图。
- **颜色**：草与叶使用相容的绿；泥土和木材有清楚的冷暖差异；石材保留中性色；水压低高频明暗反差。矿石、眼睛、危险提示使用少量更醒目的颜色。
- **空间**：近处看得出材质，中景读得出体块，远景逐渐进入与天空一致的雾。物体接地、洞穴转折、树冠分层比增加贴图噪点更重要。
- **动作**：待机、准备、出手、接触、收势分别有可辨姿态。保持响应直接，镜头抖动与特效从轻，保留减少晃动的选项。

这套方向与 Mojang 材质访谈中对清晰像素边缘和像素美术基础的讨论一致，具体调色仍以本项目的实际场景判断。[材质访谈](https://www.minecraft.net/en-us/article/try-new-minecraft-textures)、[开发者美术问答](https://www.minecraft.net/en-us/article/caves---cliffs--part-i--dev-q-a)。

## 4. 实施顺序

### M0：先清掉会破坏信任的错误

1. 修复南瓜正面、南瓜灯顶部与正面的画笔调用。当前对象方法内部把 `pumpkin_side / pumpkin_top / lamp_side` 当成独立函数调用，运行探针确认对应三种画笔返回 false。补“注册画笔实际执行成功”的检查，检查最终世界里的这些面，不能只验证名字存在。
2. 修复守卫追击速度的时间单位。`guardianAI()` 把 speed 乘 dt 作为目标速度，后续 `physics()` 又以 vel×dt 积分。最小单步探针中，配置速度 1.9 时，30/60/120 FPS 的目标速度分别仅为 0.0633/0.0317/0.0158。验证相同真实秒数下的位移与行为一致，保留受击冲量与碰撞。
3. 修复守卫落点：按地面与可站立空间选位置，禁止把建筑中心的“最上方实心格”直接当战斗地面。守卫不应在屋顶、树冠或石座上开战。
4. 核对候选包：当前包内材质/配方与源码不同。保留现有成品，生成新的审计候选包并记录版本与资源指纹，后续所有前后图基于明确版本。
5. 修复已发现的合成实际使用问题：混合橡木板/桦木板库存能手摆工作台，但一键填充仍需覆盖 2+2、1+3 等分配情况和材料不足回退。

交付：可见缺失材质清零；守卫速度与落点的针对性结果；可明确对应源码的候选包。先做针对性验证，稳定后跑相关回归。

### M1：做一套能作为标准的材质与渲染样板

先完成草土、石头、圆石、木板、原木、树叶、沙、水和深板岩这一组高频主材，在林缘、岸边、小屋、洞穴四个固定场景里判断，确定后再推广。

- 木板改为有方向、长短不一的板缝与少量木结，去掉密集编织感；土和石材降低均匀颗粒噪声；草侧边打断过长的连续亮带。
- 水面重查顶/底/内部侧面与透明排序，消除长条、拼块和层层叠色；水下用距离与深度建立能见度，保留岸边底部与鱼的轮廓。
- 天空、体素、实体统一色彩空间与雾的约定，修正浅蓝剪影和突兀的水平过渡；减少云层大块平面拼接的观感。
- 检查纹理远景采样和叶片透明边缘。运动中确有闪烁再处理 mipmap/图集边缘，不能靠模糊全画面掩盖材质问题。
- 增加轻量接触阴影或脚下投影，让生物与地面产生关系；先核对成本，再决定是否需要更完整的实时阴影。

验收：同种子、机位、天气、时刻和默认亮度的前后图；看近景也看连续铺设的 8×8 区域；岸边、水下、夜晚、火把旁都保留可读性。不能靠提高亮度或改变机位宣称改善。

### M2：把角色与第一人称资产完成度拉齐

- 先补僵尸、守卫、村民的面部和材质分区，与已贴图的动物使用同一套色阶与像素尺度。守卫明确石/金属/核心三种材质、独特轮廓和关节，不继续保留纯色方盒占位外观。
- 统一头、身体、四肢比例与关节。猪牛羊检查侧面和背面，处理羊脸对比偏硬、身体纹理与脸混用等问题；骷髅和苦力怕保留已工作的攻击预备动作。
- 空手增加手臂与握持姿态；工具使用有薄厚的像素轮廓模型或像素挤出，校准在屏幕中的尺寸、角度、光照与切换过渡。
- 命中、挥空、挖掘、放置、格挡各自有一致的视觉和声音反馈。镜头保持可控，短暂的接触停顿作用于姿态，不冻结整个游戏。

验收：每类角色前/侧/后、静止/移动/受击、白天/火把/暗处的短片；第一人称空手、镐、剑、弓、盾各一段。必须看最终游戏中的表现。

### M3：让世界具备自然空间和建造语言

- 调整地表的缓坡、陡壁、岩层露头与平地分工，减少长距离等高线式草皮横带。树木成簇、留出林间空地；花草分布有区域与疏密，群系过渡有缓冲。
- 深洞引入大小不同的洞室、窄道、上下连接和可见矿脉。目前 `deepCave()` 以地面曲面上方固定 3 格净空为主，天然容易形成低层走廊；下一版应有可探索的空间节奏。
- 增加高价值形体：优先楼梯、半砖、栅栏等能改变建筑轮廓的构件。先用它们完成一座有屋顶、檐口、窗洞、入口和地基过渡的小屋，再扩展村庄。
- 村庄和遗迹与地形衔接，避免突兀台地、截断树冠和“建筑摆在地板上”的感觉；营地、前哨、废墟分别有独特轮廓与用途。
- 守卫有专用可达空地、至少两条移动路线和清楚的掩体；石座、守卫、箱子的位置让玩家能理解战前准备、交战与领奖。

世界生成改动使用明确版本，新档采用新规则，已有世界的建筑、编辑与版本语义保持。上限扩高会影响内存、网格和存档约定，作为独立技术任务评估；当前先改善已有范围的构图与空间。

验收：三个固定种子分别从地表走到一个自然地下入口，村庄与战场均可步行进入；不能只拍高空俯视图。旧档抽查建筑、容器与区块边界。

### M4：把战斗、生态和成长接成有趣的过程

- 守卫的光弹改成可见、具有飞行时间的投射物，前摇锁定方向、玩家可通过侧移或掩体应对；若保留瞬时射线，则改为明确的激光设计，给瞄准线和持续蓄能表达。主方案优先复用现有投射物链路。
- 横扫有可读范围与转向约束、硬直有真实反击机会。一次完整交战能经历观察、闪避/格挡、反击，而不是站桩连续扣血。时长只作诊断，不靠堆血凑战斗时长。
- 评估并实现副手盾这一独立操作项，让武器与防御可以自然配合；库存/存档缺字段默认空，旧档兼容。保留格挡角度、耐久与交互对象优先级。
- 复用已有跟随、惊逃、繁殖和鱼鸟行为，先修“墙边、岸边、坡地卡住后不换目标”的问题。按种类补少量可见活动；先做局部绕障与脱困，不贸然重写全局寻路。
- 形成两个有效选择，例如先建庇护所/种植补给，或带有限补给探索营地、采矿备装；材料、工具、危险与奖励彼此解释得通。

验收：弓箭可侧移躲避，盾牌格挡反馈明确，守卫攻击有真实反制；墙角/岸边/台阶上的连续行为测试；铁级正常装备能够通过合理操作胜利，死亡后可重试、奖励只发一次。

### M5：收敛 HUD、声音与前 20 分钟体验

- 主菜单展示本作实际世界画面或缓慢全景，保留清楚的中文标题与入口；技术、引擎和许可说明移到关于页。
- 背包统一格子尺度、字体层级与物品图标；关键文本提高可读性。方块物品采用一致的体积图标，避免全部只是平面纹理卡片。
- 提示设优先级：危险预警最高、当前交互其次、发现/成就短暂、长期目标可收起。首次接近遗迹不同时堆三四条横幅。材料线索先用世界语言表达，坐标说明留给详细帮助。
- 设置增加 UI 缩放、减少视角晃动和更直观的灵敏度说明；检查键盘焦点、弹窗返回和不同分辨率。这里是风险复核，不宣称已完成可访问性认证。
- 音频先做默认混音：操作反馈和危险提示清楚，探索音乐有留白，夜间与洞穴转换平顺。音乐、环境、音效分别控制，导出同一条真实输出链的 A/B 样本供试听。
- 音频自动检查允许音乐的自然静默段；用受控音效/已知含信号片段检查采集链，不为满足一个短窗口非静音而强行改变夜间氛围。

验收：1280×720 与 1920×1080 的 HUD/背包/设置图；新玩家不看开发文档能制作首套工具、理解避险和发现下一步；试听者对音效抢占、循环与突变给出具体反馈。

### M6：用同一个最终 EXE 验收完整体验

从正常生存新档完成砍树、合成、鱼鸟观察、下矿、熔炼、备装、发现入口、解封、战斗、领奖、保存退出重进。记录真实耗时、卡点、死亡、物品来源和连续证据。

这条路线独立于主线/守卫自动场景，可分段合法保存后继续；不能用创造发装备、传送、直接修改方块或引用另一份战斗报告代替。现有 A/B 混合布置脚本可继续做冒烟验收，报告名称与结论应体现其边界。

交付同一份包的源码/资源对应记录、相关回归、真实进程退出码、完整路线与 10 个固定场景的前后证据。成品普通 saves 不清空，验收存档与报告独立。

## 5. 多 agent 协作方式

每个工作包有一个负责人和一个可见产物，所有包共用 M1 确立的色板、像素密度、模型比例和默认截图条件。美术统筹负责选择一致方案与最终整合；其他 agent 可以并行做独立模块，但共享 `painters.js / mobs.js / game.js` 的落地由明确负责人合并，避免同时覆盖。

建议分工：环境材质与渲染；角色/第一人称；世界结构与建造；战斗/流程；最后由整合负责人统一包与体验验收。这里是实施分工建议，本次没有启动或向其他 agent 发送任务。

每个包提交时说明玩家能看见或操作到的变化，附固定条件前后证据和相关验证。功能测试是基础，审美验收由同一负责人看实际游戏。新素材只在适配既定风格后采用，保留来源、许可和加工记录。

## 6. 第一轮完成的定义

- 正常世界无南瓜紫黑缺失材质，守卫不再随帧率变慢、不在屋顶开战。
- 岸边、小屋、林缘、洞穴四场景具备一致的主材和渲染风格。
- 僵尸与守卫完成材质，空手和常用工具的第一人称表现完整。
- 玩家能在实际场地中看懂并应对一轮完整守卫攻击。
- 当前提交、候选 EXE 和报告对应；旧存档检查通过。

第一轮完成后再推进更大范围的洞穴/群系与建造构件；第一轮出现明显的画面回归就先收敛。计划的效果以实际画面、操作和完整流程判断，不能用新增方块数、下载素材数或断言总数替代。
