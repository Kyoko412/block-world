# 视觉阶段二通宵计划：装备成长、战斗反馈、目标与声音

> 用途：交给后续代理连续执行。本文是执行计划，不代表这些功能已经实现。
> 项目：`E:\MinecraftOffline`
> 当前真实基线：单测 `80/80`；源码 e2e `313/313`（连跑两遍）；成品自检 `313/313`、`EXITCODE=0`、`ERRORS=0`。
> 当前视觉阶段一可能仍以未提交改动存在。任何情况下都不得用 reset / checkout / clean 覆盖它。
> 用户原有未跟踪文件《内容与质感提示词.md》不得修改、删除或提交。

## 一、今晚目标与边界

按以下优先级，把游戏从“画面更像 MC”推进到“前期成长更像 MC”：

1. 皮革 / 铁 / 钻石护甲，形成采集 → 合成 → 装备 → 减伤 → 耐久消耗闭环。
2. 盾牌与方向性格挡，让近战和骷髅箭有不同应对方式。
3. 八个前期成就与少量战斗反馈，让玩家前十分钟有目标。
4. 三首有明确动机的程序化音乐与四类环境床，改善长时间游玩的氛围。
5. 前四项完整验收后仍有余量，才做最小可用 TNT，消除火药的孤儿用途。

今晚不做：村庄、村民交易、附魔、红石、新维度、Boss、末影人、第三人称护甲模型、
复杂 TNT 连锁、水中爆炸规则、大规模地形重写或又一次材质全面重绘。

## 二、不可违反的项目约束

- 不改 `app/renderer/vendor/three.module.js`，不改 `app/package.json` 依赖。
- 不联网下载，不安装依赖，不引入外部图片、字体、音频；继续使用程序化素材。
- 保持 Electron + Three.js、完全离线、浏览器/桌面双模式与旧存档兼容。
- 不大规模重构、不改目录结构。
- 既有测试只许新增断言，不许删除、改名绕过、改弱阈值或为新功能调整旧期望。
- 新机制必须接入真实输入与真实主循环，不能只有物品表、图标或直接调用测试 API 的演示。
- 禁止裸跑 `方块世界.exe`；只能带 `--selftest` 或通过 `selftest-package.ps1` 启动成品。
- `pack.js` 与成品自检禁止并行。
- e2e 工具超时至少 `600000ms`；不用会杀掉进程组的短超时。
- 物理、战斗、生成与动画测试使用 `until/watch` 和墙钟预算，不写固定帧数等待。
- 每轮绿灯必须交叉核对：退出码、`pass=total`、`errors=[]`、总数=上一轮基线+新增数。
- 测试日志仍有既存 `texImage3D` WebGL 警告。不为其修改 vendor，也不得宣称没有 WebGL 警告。

## 三、提交与进度纪律

本计划允许后续代理在每个完整任务全绿、文档同步后创建本地 commit；禁止 push、禁止改 git config、
禁止跳过 hooks。commit 是回滚检查点，不是完成证据；没有四道门禁就不能提交为完成。

`长期作业进度.md` 是唯一进度真源。每个任务都要更新：
- 当前单测 / e2e / 成品自检基线；
- 在飞文件和下一个任务；
- 新增断言对账，例如 `313 → 321（+8，护甲）`；
- 原始先红输出、实现中的真实回归、最终门禁数字；
- commit hash、截图或 WAV 证据路径；
- 未完成项与已知限制。

## 四、统一验收门槛

每个任务完成后按顺序执行，不许并行跑 pack 与 selftest：

```bash
cd app
node --test tests/world.test.js
npx electron tests/e2e-electron.mjs
npx electron tests/e2e-electron.mjs   # 同一代码独立复跑
node tools/pack.js
cd E:\MinecraftOffline
powershell -NoProfile -ExecutionPolicy Bypass -File app/tools/selftest-package.ps1
```

通过后还要：
1. 读取 `artifacts/e2e-report.json`，确认 `done=true`、`pass=total`、`errors=[]`。
2. 读取包内 `saves/selftest-report.json`，确认相同口径和新增断言都在。
3. 比对本轮改动源码、测试剧本与包内对应文件的 md5，要求 `RENDERER_DIFF=0`。
4. 对界面、手持、战斗或天空改动采集真实截图并人工查看，不以断言代替视觉核对。
5. `git diff --check`，审查最终 diff 和 status；不得误改禁改文件或用户提示词。

## 五、执行顺序与时间盒

建议总预算约 7～9 小时。若时间不足，保留前序完整成果，后续任务原样留队，不赶工出半成品。

### P0 接手、基线保护与伤害链审计（20～30 分钟）

先做：
1. 读 `长期作业进度.md` 的续跑指令、已知坑、已完成和体检记录。
2. 读 `验收报告.md` 第一、二、三节。
3. `git status --short`、`git diff --stat`、最近提交日志。
4. 核对视觉阶段一改动完整，禁止回滚；若尚未提交，按上一轮已验证范围单独建立基线 commit。
5. 复跑单测与一次源码 e2e，确认起点仍是 80/80、313/313。
6. 阅读物品、配方、背包、输入、交互、伤害、生物箭矢、爆炸、UI、音频和存档相关文件。
7. 列出所有伤害入口及分类：近战、生物箭、爆炸、坠落、溺水、饥饿、仙人掌、其他。
8. 列出右键优先级：可交互方块、床、喂食、弓、进食、放置、盾牌，避免盾牌吞掉旧交互。

产出：在进度文件写一小段审计结论与今晚队列，不新建另一套进度真源。
完成标准：基线可复现，伤害与右键调用链明确，没有业务代码改动遗漏审计。

### P1 护甲成长闭环（90～120 分钟）

#### 实现范围

- 皮革、铁、钻石三套：头盔、胸甲、护腿、靴子，共 12 件。
- 使用现有皮革、铁锭、钻石及经典合成图案；每件有程序化 16×16 图标。
- 背包加四个专用装备格，支持装备和取下；保留原 36 格、拖拽、右键与 Shift 点击语义。
- HUD 显示护甲值，不改变生命、饥饿、气泡和快捷栏布局。
- 护甲有耐久；耐久归零后装备消失并刷新护甲值。
- 减伤纯函数建议：每点减免 4%，封顶 80%；皮革总 5 点、铁 15 点、钻石 20 点。
- 只减免明确标记的战斗伤害：近战、生物箭、爆炸；不减免坠落、溺水、饥饿、仙人掌。
- 每次实际承受可减免伤害时，当前已穿护甲各扣 1 耐久；未受伤、创造模式、不可减免伤害不扣。
- 装备格、物品和耐久随存档恢复；旧档缺字段按空装备处理。

#### 保守取舍

不做韧性、附魔、护甲摆动模型和复杂伤害穿透。若集中伤害入口需要大规模重写，
先加兼容的可选伤害类型参数，再逐点接线，保持旧调用默认行为不变。

#### 必测内容

- 公式：0 点、普通值、20 点封顶及非法输入边界。
- 12 件物品、配方、图标、创造栏分类齐全。
- 真实装备/取下后护甲值变化，物品不复制、不丢失。
- 同种战斗伤害下，无甲与有甲结果符合公式；不可减免伤害保持一致。
- 耐久只在正确事件扣除，损坏后装备格与护甲值同步。
- 真实生物近战和骷髅箭走完整伤害链。
- 存档往返、旧档兼容。

证据：背包装备格 + HUD 护甲值截图；一条真实有甲受击 e2e 读数。
通过统一门禁、更新文档后，才允许进入 P2。

### P2 盾牌与方向性防御（75～100 分钟）

#### 实现范围

- 6 木板 + 1 铁锭合成盾牌；独立图标与第一人称模型。
- 手持盾牌右键开始格挡，松开结束；格挡时适度减速，不能同时攻击或放置。
- 只格挡正面约 120° 扇区内的近战与箭矢；背后攻击和爆炸不穿盾。
- 成功格挡才扣耐久并播音效/粒子；只举盾不受击不扣耐久。
- 切走物品、打开界面、死亡、暂停、回菜单时清理格挡状态与减速。
- 对准箱子、工作台、床、可喂食动物等对象时保持旧交互优先；无交互目标才举盾。
- 格挡状态不必入库；盾牌物品与耐久必须保存。

#### 必测内容

- 正面近战格挡、背后近战受伤。
- 正面骷髅箭格挡，箭与玩家状态符合设计。
- 格挡耐久、松键恢复、切栏/开界面/死亡清理。
- 右键箱子与喂食不被盾牌吞掉。
- 真实输入进入/退出格挡，不用直接设置内部布尔值替代全部链路。
- 存档恢复与创造栏可见。

证据：持盾第一人称截图、背包盾牌截图、正面/背后伤害对照读数。
若 P1 未全绿，不得开始 P2。

### P3 战斗反馈与八个前期成就（70～90 分钟）

#### 战斗反馈

- 区分近战命中、盾牌格挡、玩家受伤、护甲损坏的音效和少量视觉反馈。
- 沿用现有挥动、击退、闪红和粒子，不引入强制攻击冷却，不改旧伤害数值。
- 同类音效可轻微 detune / 音量变化；防止削波、爆音和无限叠加。

#### 成就

仅做八个：获得木头、制作工作台、获得圆石、制作熔炉、获得铁锭、
穿上任意护甲、制作盾牌、获得钻石。

- 由真实获得、合成、装备事件触发，不靠每帧全量扫描伪造事件。
- 完成时用不挡准星的像素 toast；背包或暂停界面可查看进度。
- 同一存档只解锁一次；存档恢复；旧档可安全初始化。
- 不做奖励点数、排行榜、Boss 或传送门。

#### 必测内容

- 木头 → 工作台 → 圆石 → 熔炉的连续真实事件链。
- 护甲 / 盾牌 / 铁锭 / 钻石成就按事件触发。
- 重复事件不重复解锁、不重复刷屏。
- 读档后完成状态保留，旧档不报错。
- 战斗反馈接入真实命中/格挡路径。

证据：连续成就 toast 截图或分步截图、成就面板截图、存档往返读数。

### P4 音乐与环境声重构（90～120 分钟）

#### 三首主曲

- 白天：72～84 BPM，明亮五声音阶，8 小节；拨弦 + 柔和 pad + 轻低音。
- 夜晚：58～66 BPM，稀疏音乐盒/钟琴 + 低音 pad，保留留白。
- 洞穴：无强固定节拍，低频 drone + 偶发滴水，避免持续高压。

每首必须有明确主题动机，并在 8 小节内重复或变化重复；不得继续只用纯随机音符。
同时最多一首主曲，切轨交叉淡化 2～4 秒，快速切换也不能叠加多条循环。

#### 环境床

先做风、夜间虫鸣、洞穴滴水、雨声。按昼夜、天气、玩家高度/环境切换。
音乐、环境、音效分轨并遵守现有设置。未获得用户手势前不得强行播放；
暂停、回菜单与销毁时正确释放。

#### 可观测与证据

- 暴露只读诊断：`trackId`、`activeMusicCount`、`activeAmbient`、段落或等价信息。
- 使用现有 WebAudio / OfflineAudioContext 渲染每首至少 20 秒 WAV 到 `artifacts/audio/`。
- 自动检查非静音、峰值不削波、循环附近无异常跳变、切轨后活跃主曲不超过一首。
- 检查雨天雨声、夜晚虫鸣、洞穴滴水与设置开关。
- 机器检查与人工试听分开记录；只生成 WAV 不得写成“已人工试听”。

若音频部分受阻，优先保住“三首有动机、单主曲、设置正确”的最小版本，
环境床可完整留到下一轮，但不能留下持续叠音或无法停止的半成品。

### P5 可选：最小可用 TNT（60～90 分钟）

只有 P0～P4 全部完成且仍有余量才能开始。

- 4 沙 + 5 火药合成 TNT；1 铁锭 + 1 燧石合成打火石。
- 打火石右键点燃，3 秒引信、闪烁和音效，之后复用 `core/explosion.js`。
- 破坏走 `world.setBlock`、脏标记、光照、网格和存档 diff 的既有链路。
- 最小版只做单体手动点燃；连锁和复杂水中规则不做半成品。
- 验证只引爆一次、坑洞与范围、生存伤害、创造免伤、存档往返、配方与耐久。
- 若无法在本时间盒完成，停止并留下明确待办，不影响前面已提交成果。

## 六、夜间完成定义

每个任务只有同时满足以下条件才算完成：

- 新断言先在旧实现上红，并保留原始失败输出。
- 新内容可通过真实玩法获得、使用、保存；不是只添加定义。
- 单测全绿；源码 e2e 连跑两遍全绿；打包成功；成品自检 `EXITCODE=0`。
- 总条数对账正确，新增断言在最终报告中逐条可见。
- 源码与包内 md5 一致。
- 截图或 WAV 证据真实、可打开；界面没有遮挡准星/HUD。
- 文档、操作说明、内容数量与实测一致。
- 工作区没有临时调试脚本、无关文件或用户提示词改动。
- 已创建一个只包含该任务完整内容的本地 commit。

## 七、阻塞与降级规则

- 同一外部问题连续阻塞两次：保留原始错误，停止该任务，不反复盲试。
- 范围膨胀时先砍非核心视觉和额外配方，不砍测试、存档兼容和输入清理。
- 不用修改旧断言来兼容新设计；新设计必须尊重旧行为。
- 不把偶发失败直接归咎于机器。先独立复跑，再比较相同断言、世界状态与读数。
- 不为赶进度同时开多个功能文件战线；一个任务未闭环，不开下一个。
- 时间不够时停在最近一个全绿 commit，并写清下一任务的第一个具体动作。

## 八、早上收尾顺序

1. 最后复跑单测与一次源码 e2e；若刚重新打包，再跑成品自检。
2. 查看 `git status --short`、`git log --oneline -15`，确认 commit 链和未提交残留。
3. 汇总实际完成项、每项 commit hash、最终单测/e2e 条数、包内自检结果。
4. 列出所有新截图、WAV、报告路径，并标明哪些经过人工查看/试听。
5. 更新 `长期作业进度.md` 的“明天从哪继续”，剩余工作写具体，不写空泛“继续优化”。
6. 最终回复只报告可证实结果：完成内容、门禁数字、commit、证据路径、已知限制。
