## 1. 目标与判断标准

玩家反馈：UI、音乐、材质、生物动作、生物美术、方块美术都「不太行」，整体不好玩。

判断（已与用户对齐过方向）：这些不是六个独立问题，是两层——
- **A 层「世界有没有回应你」**：动作、反馈、节奏。决定「好不好玩」，成本低、风险低。
- **B 层「画面精不精致」**：静态资产。决定第一眼，成本高、边际收益低。

**唯一判断标准：玩家每秒能否得到世界的回应。** 凡是增加「东西的数量」而不增加「回应的密度」的改动，一律不做。

已核实的反直觉事实（别再重复劳动）：
- `gfx/painters.js:16` 已有统一 `TILE=16` 网格，`:180` 有集中调色板 `C` 与 `tone/mix/speckle` 共享画笔，`atlas.js:13` 是 16 列图集；注释写明「低一档饱和度、收窄明暗噪声」——**视觉阶段二已专门收敛过一轮材质**。重画 73 张贴图边际收益最低。
- `world/mobs.js:854-865` 的 `render()` 只有腿部 sin 摆动、敌怪双臂恒定 `-1.4`、受伤闪红，**没有任何攻击/受击/转头/闲置姿态**。
- `e2e-scenario.js:339`（`6.1a`）把面板背景钉死 `rgb(198,198,198)`、槽位 `rgb(139,139,139)`；`19.2` 钉图集覆盖；`MU.1~8` 钉主曲切换/单曲数量/暂停释放/开关；`AN.*`/`V4.*`/`V5.*` 钉玩家手持姿态读数。**UI 只能加层，不能换皮；音乐触发机制不能改。**

## 4. 环境坑（必读，踩过好几次）

1. **宿主注入 `ELECTRON_RUN_AS_NODE=1`**，会让 `electron.exe` 退化成纯 Node，`npx electron` 报 `cjsPreparseModuleExports` 错。所有 Electron 命令必须：
   `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS ./node_modules/electron/dist/electron.exe ...`（在 `app/` 目录跑）
   成品 exe 同理要带 `env -u ...`。
2. `git commit` 末尾可能出现 `PROGRAM BLOCKED BY SECURITY POLICY - reg.exe` 警告，**提交其实已成功**，用 `git log` 确认即可，不要重试该程序。
3. **既有断言偶发红**（都不是本轮故障，重跑即恢复，不要改断言）：
   - `AC.8`：runner 窗口瞬时缩到约 203px → `achRect.x=-1`；正常 `x=1079`。
   - `V5.4`：僵尸 8 秒内没咬到盾 → `hit=false hp=9`；正常 `hit=true hp=20`。
   两者都因窗口尺寸/怪物时序波动；重跑一遍并在文档如实记录。
4. e2e 里凡「等条件」一律 `until/tryUntil` + 墙钟预算，**不要写固定帧数**（历史翻车 5 次：T3.9 / 回归.17/18 / SP.2 / 10.2）。
5. `pack.js` 只复制 renderer / `e2e-scenario.js` / `LICENSES.md` / `操作说明.md` 等，**不复制根目录 README、验收报告、长期作业进度**，打包后改这些文档不影响成品一致性。
6. `testApi` 是唯一允许注入测试读数的口子；新增读数只增不减。
7. 新增 e2e 章节用**独立块 `{ ... }`** 包起来，避免 `q*`/`fl*` 之类临时变量与前面 58 节重名（曾因此 `Identifier 'qtx' has already been declared`）。

## 5. 阶段 A · 生物动作与反馈（本夜第一段，优先做）

**玩家能感觉到的变化**：打怪/被咬时敌人会抬手前挥、受击会缩身后仰并轻微侧倾、闲置时会缓慢张望和呼吸；生物不再是「会平移的盒子」。

**任务**：
1. 把姿态计算抽成**纯函数** `computePose(m, dt)`（导出，可无头单测），返回 `{arm0, arm1, headX, headY, bodyScaleY, tiltZ}`；`render()` 只负责把结果应用到 `parts`。
2. Mob 构造加不入库字段：`animAttack`（攻击姿态剩余秒）、`animIdle`（闲置相位）。受击复用既有 `hurtT`。
3. 三个真实事件点各加一行赋值：骷髅射箭（`mobs.js:609`）、近战攻击（`:616-621`）、狼扑（`:700`）→ `m.animAttack = 0.36`。`hitMob()` 打断攻击姿态。
4. `render()` 应用姿态；**保持 `m.mesh.rotation.y = m.yaw` 不变**（D3 倒退走回归钉死这条），只动 `rotation.z` 与部件旋转，不动 `position`、碰撞、AI、生命周期。
5. `testApi` 新增 `mobPose(i)` 只读诊断（type / animAttack / hurtT / arm0 / arm1 / headX / headY / bodyScaleY / tiltZ / yaw）。
6. 单测 +3、e2e +5（`A.1~A.5`），`EXPECTED_TOTAL` 同步 +5。

**明确不做**（无人值守期间最容易翻车的地方）：死亡倾倒/淡出（要改生物生命周期，会撞 `V4.*`/`SL.*`/`TN.*`）、改 AI、改模型文件、加新生物、加新音效文件。死亡姿态留到 A2 单独回归。

**改动面**：`app/renderer/js/world/mobs.js`、`app/renderer/js/player/game.js`（只加 testApi）、`app/tests/world.test.js`、`app/tests/e2e-scenario.js`。

**验收点**：
- 单测：纯函数在无动画/攻击峰值/受击/闲置四种输入下的角度范围与「受击打断攻击」优先级；`rotation.y` 不受影响。
- 真实 e2e：生成僵尸 → 触发攻击 → `arm0` 明显低于基线 `-1.4`；`hitMob` → `tiltZ ≠ 0` 且 `headX > 0`；闲置时 `headY` 在 ±0.22 内变化；`animAttack` 会自然衰减回 0；`mesh.rotation.y === yaw` 恒成立。
- 既有 `AN.*` / `V4.*` / `SP.*` / `CF.*` / `Z.*` / `SL.*` / `WL.*` / `D3` 全部照常通过。

**回滚点**：以 `10958fa` 为基线；若任一既有生物断言变红且 20 分钟内定位不了，`git revert` 本段提交。

**Stop / 降级条件**：若 `mobPose` 读数依赖改生命周期或动到 `rotation.y`，立即降级为「只做闲置转头 + 呼吸」，砍掉攻击/受击姿态。

**预计**：4–6h（含门禁）。
