## 4. 色彩 / 洞穴 / 远景：改前改后与人工看图

同条件 A/B：种子 `visual-audit-2026`、时间 0.3、晴天、1280×720 窗口，独立目录不覆盖旧证据。

- `artifacts/visual/ab-20261106-colorfix-before2/c2-cave-sealed.png`（HEAD 光照 + 旧曲线）
- `artifacts/visual/ab-20261106-colorfix-after2/c2-cave-sealed.png`（四条泄漏全修 + 光池曲线）
- `artifacts/visual/ab-20261106-colorfix-after2/{c-cave,g-treeline,a-grass}.png`
- `artifacts/visual/ab-20261106-colorfix-night/h-night-torch.png`（新增夜间火把排场景）

人工逐张看过 6 张，结论：

- **改前**的石室像被日光灯照亮的地下室：天花板、远墙、地面一样亮，火把周围没有光池，整片是饱和度 0 的灰。
  读数佐证：室内 `sky=13~15`（`floor` 甚至 15），ground 区域 `mean 0.3073 / contrast 0.0676 / saturation 0.0313 / warm 0.0096`。
- **改后**：火把近处明显更亮且偏暖，远墙、天花板、四角压下来，石头纹理在暗处仍可读（没被乘成纯黑）。
  读数：室内 `sky=0`、`block` 呈 `14 → 12 → 11 → 8` 的梯度、`brightDay == brightNight`（室内不再随白天变亮）；
  ground 区域 `mean 0.1596 / saturation 0.1427 / warm 0.0235`（饱和度与暖度**上升**，因为现在看到的是火把色温而不是假阳光）。
- **远景**（`g-treeline`）：远处丘陵与天空有明确的轮廓和色差别，没有融成一片；该场景 ground/horizon/center 三个区域
  的统计与改前**逐像素相同**，sky 区只差 0.0008 —— 说明本轮没有动雾与天空（审计确认它们本来就在同一色彩空间里自洽）。
- **白天没有变暗**（用户点名的硬约束）：`a-grass` ground `0.4362 → 0.4348`（−0.3%，噪声级），
  而且这是结构性保证 —— shader 里白天/天空光那条曲线 `0.065+0.935*pow(lvl,1.12)` 一个字符都没改，
  白天露天的 `blkDom=0` 使新旧逐像素同值。灰阶对照表（纯函数算的，写进 `长期作业进度.md`）里
  「白天露天草地 / 白天露天火把旁 / 夜间无火把月光基线」三行差值都是 **0.0**。
- 没有使用全屏遮罩、暗角或统一乘暗系数：`EL.2`/`P0.3` 断言里明确检查了 shader 源码不含 `gl_FragCoord`。

## 5. 生物：白天 / 无光 / 火把旁的截图与读数

- 截图：`artifacts/visual/ab-20261106-entitylight/j-mob-light.png`
  （夜间草地、一支火把、猪/羊/苦力怕/僵尸由近到远排成一列），meta 里带每只的 `sky/block/shade/color/base`。
- **这张图能证明的**：四只生物的材质色都被压到夜间水平，且与各自底色成比例 ——
  猪 `0xe89a9a → 0x543838`、羊 `0xecebe3 → 0x565552`、苦力怕 `0x4faf4a → 0x1d3f1b`、僵尸 `0x2f6a52 → 0x11261e`，
  四只的 `shade` 都是 `0.3628`（= `entityBrightness(sky 15, blk 0, uDay 0.36)`）。改之前它们是纯色贴纸，
  夜里和正午一个亮度。
- **这张图不能证明的**：火把对生物的提亮。图里四只生物的眼睛格读数全是 `sky 15 / block 0`，连贴着火把那只猪也是 0；
  我把 `world.pending()` 的 `light/gen/mesh` 全排空之后重拍，读数一样。
  但**同一份代码**在两个地方是亮的：
  - e2e `EL.1`（真实游戏窗口）：猪的眼睛格 `sky 7 / blk 13` → 材质色 `0xc28181`（`k=0.838`），
    深处无光格 `0x251919`（`k=0.16`），白天格 `0xe89a9a`（`k=1`），亮度顺序 `87 < 452 < 540`；
  - 无头 `VoxelWorld` 探针（照取证脚本一模一样的平台 + 火把 + 排空补光）：猪那一格 `block=12`、
    它上面一格 `13`、羊格 `9`、苦力怕格 `4`。
  所以结论是：**「火把旁生物会变亮」用的是 `EL.1` 与无头探针，不是这张图**；
  取证脚本那个场景的现场状态有问题（最可能是同一次 `evl` 里建造 / 传送 / 补光的先后顺序），列为待复验项。
- 顺手记下的坑（写进 `长期作业进度.md`）：`T.waitChunks(n)` 只等 `genQueue` 与 `dirtyMesh`，**不等 `dirtyLight`**；
  而 `world.getLight` 对还没点亮的区块返回「y 高于纯函数地表就当 sky 15、block 0」的近似 ——
  取证脚本要在建造之后读光照，必须自己排空 `world.pending().light`。
- `EL.2` 核对两边同源：`scene.fog` 的颜色与 `uFogColor` 相同、`near/far = 44/88` 与体素 uniform 完全一致、
  体素 `matOpaque.fog === false`（否则 three 会来刷我们没声明的 fog uniform 而崩溃）、
  JS 曲线的四个点与 shader 源码里那两组常数互相吻合。
